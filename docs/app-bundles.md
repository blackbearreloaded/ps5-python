# Python app bundles

The project supports multiple Python applications under one shared runtime.
Each application has its own entry script, pure-Python libraries, assets, and
metadata.

```text
/data/python/
├── runtime/
│   ├── python.elf
│   └── cpython-lib/
└── apps/
    ├── flask_dashboard/
    │   ├── app.json
    │   └── main.py
    └── .shared/
        └── serve.py
```

The local source layout mirrors the PS5 layout:

```text
apps/flask_dashboard/
├── app.json
├── main.py
├── lib/
└── assets/
```

## Manifest

The first manifest format is intentionally small:

```json
{
  "id": "flask_dashboard",
  "name": "Flask PS5 Dashboard",
  "version": "1.0.0",
  "entry": "main.py",
  "runtime": "shared",
  "mode": "web"
}
```

The deployment tool currently requires `entry` and rejects absolute or parent
directory paths. `mode` is optional and defaults to `web`; use `script` for a
regular process-backed program that prints output and exits instead of serving
HTTP. The browser displays the mode and lets the user provide optional
command-line arguments. They are parsed with shell-style quotes and exposed to
the entry script as `sys.argv[1:]`.

## Module and asset paths

The native launcher adds both of these paths to CPython's module search path:

```text
/data/python/apps/<id>/
/data/python/apps/<id>/lib/
```

This allows an entry script to import app-local modules:

```python
from greeting import build_message
```

The practical web examples also add `/data/python/apps/.shared` to
`sys.path` for the common cooperative server loop.

The launcher also sets `__file__` to the real PS5 entry path. Applications
should derive asset paths from it rather than assuming a current working
directory:

```python
app_dir = __file__.replace("\\", "/").rsplit("/", 1)[0]
asset_path = app_dir + "/assets/index.html"
```

## Build and deploy

### Prepare dependencies on the host

Dependencies are installed during preparation, not on the PS5. Add a
`requirements.txt` beside the manifest, or declare a short `dependencies`
list in `app.json`, then run:

```sh
make package-app APP=apps/myapp
```

This invokes the host Python's pip with the CPython **3.14** target and
`--only-binary=:all: --platform any`, installing universal pure-Python wheels
into the app's `lib/` directory. Package metadata directories are removed
because the current PS5 FTP filesystem cannot create dotted metadata paths.
The helper rejects native extensions; those require a PS5-compatible build and
static interpreter integration instead.

For example:

```text
apps/myapp/
├── app.json
├── requirements.txt
├── main.py
└── lib/                 # generated by make package-app
```

The resulting app directory is self-contained and can be validated and
deployed normally:

Validate an app on the host:

```sh
make host-app APP=apps/flask_dashboard
```

Deploy it to the PS5:

```sh
PS5_HOST=192.168.4.30 make ps5-app APP=apps/flask_dashboard
```

The app mode stores the shared interpreter under `/data/python/runtime/` and
the selected bundle under `/data/python/apps/<id>/`. The normal `ps5-run`
target remains available for one-off scripts. Each launched app still runs in
its own supervisor-managed child process, regardless of whether its mode is
`web` or `script`.
